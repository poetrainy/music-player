# アダプタ実装ガイド

音楽サービスを差し替え・追加する際に、vendor（`src/service/vendors/<vendor名>/`）に何を用意すればよいかをまとめる。全体のアーキテクチャ概要は [機能仕様書](./機能仕様書.md) の「アーキテクチャ（外部サービス連携）」を参照。

## 全体構成

```
src/service/
├── adapter.ts   — ServiceAdapter インターフェース + 有効な vendor の選択（サーバー専用）
├── player.ts    — PlaybackController インターフェース + 有効な vendor の選択（ブラウザ専用）
└── vendors/
    └── <vendor名>/
        ├── api.ts        — 外部サービスへの生 HTTP クライアント
        ├── adapter.ts     — ServiceAdapter の実装
        ├── player.ts      — PlaybackController を生成する再生エンジンの実装
        └── authScope.ts   — OAuth スコープなど認証関連の定数
```

`adapter.ts`（データ取得系）と `player.ts`（再生系）が分かれているのは Next.js のサーバー/クライアント境界のため。

- `serviceAdapter`（`adapter.ts`）は `auth()` セッションを使うため**サーバーでしか動かない**。`src/features/playlist/api.ts`・`song/api.ts`・`user/api.ts` など、サーバー側の `api.ts` からのみ呼び出すこと。
- `createPlaybackController`（`player.ts`）は DOM 操作を伴うため**ブラウザでしか動かない**。`src/features/player/hook.ts`（`"use client"`）からのみ呼び出すこと。
- 1つの vendor 実装がこの両方にまたがって構わない（YouTube vendor は両方持っている）が、**呼び出し元を混同しない**（サーバー専用の値をクライアントに渡そうとしない、逆も然り）。

## 新しい vendor を追加する手順

1. `src/service/vendors/<vendor名>/` を作成し、下記の各セクションに従って `api.ts`・`adapter.ts`・`player.ts`・（必要なら）`authScope.ts` を実装する。
2. `src/service/adapter.ts` の `serviceAdapter` が指す先を新しい vendor の adapter に変更する。
3. `src/service/player.ts` の `createPlaybackController` が指す先を新しい vendor の player に変更する。
4. 認証方式が Google OAuth と異なる場合（例: サービス独自の OAuth）は `src/auth.ts` の NextAuth プロバイダ設定自体の変更が必要。単に呼び出す API のスコープが違うだけなら `authScope.ts` の値を差し替えるだけでよい。
5. `Song.thumbnailUrlSmall`/`thumbnailUrlLarge` など、サムネイル URL のようにサービス固有のロジックで解決するフィールドは vendor の `adapter.ts` 内で組み立てる（entity 自体はサービス非依存の形を維持する）。

## `api.ts` に用意するもの

外部サービスへの生の HTTP 通信のみを担う。認証ヘッダーの付与、エンドポイント URL の組み立て、リクエスト実行が中心。

- アクセストークンの取得（`auth()` セッションから、あるいはサービスが求める方式で）
- GET/POST/PUT/DELETE 等、必要な HTTP メソッドのラッパー関数
- API 呼び出し回数・クォータの計測が必要なサービスであれば、その記録処理（YouTube vendor では `getQuotaUsage`／`recordApiUsage` として実装）

`gapi.client.youtube.*` のような、そのサービス固有のレスポンス型はこのファイル（または `adapter.ts`）に閉じ込め、`src/features/**` 側には一切漏らさない。

## `adapter.ts` に用意するもの — `ServiceAdapter` の実装

`src/service/adapter.ts` で定義している以下のインターフェースを満たす。

| メンバー | 役割 |
| --- | --- |
| `authScope: string` | NextAuth の OAuth スコープ文字列（`src/auth.ts` から参照される） |
| `getPlaylists(): Promise<Playlist[]>` | ログインユーザーの全プレイリストを取得（曲一覧も含む） |
| `getPlaylistById(playlistId): Promise<Playlist \| null>` | プレイリスト詳細を1件取得。存在しなければ `null` |
| `registerPlaylistSong(playlistId, songId): Promise<string>` | プレイリストに曲を追加し、追加された項目の ID（`playlistItemId` 相当）を返す |
| `updatePlaylist(playlistId, title): Promise<void>` | プレイリスト名を変更 |
| `deletePlaylistSong(playlistId, playlistItemId): Promise<void>` | プレイリストから曲を削除 |
| `getSongsByIds(songIds): Promise<Song[]>` | 曲 ID の配列から曲情報をまとめて取得 |
| `searchSongs(query): Promise<Song[]>` | キーワードで曲を検索 |
| `getQuotaUsage(): Promise<QuotaUsage>` | API 利用量（クォータ）の現在値・上限・リセット時刻を返す |

返却する `Song`／`Playlist`／`QuotaUsage` は `src/features/song/entity.ts`・`src/features/playlist/entity.ts`・`src/features/user/entity.ts` で定義されたサービス非依存の形。`Song.thumbnailUrlSmall`/`thumbnailUrlLarge` のように、実体（動画 ID など）からサムネイル URL を組み立てる処理はここで行う。

プレイリスト変更系（`registerPlaylistSong`・`updatePlaylist`・`deletePlaylistSong`）は Next.js の `revalidatePath` によるキャッシュ再検証もここで行う（呼び出し元の `src/features/playlist/api.ts` 側は `"use server"` の境界を保つだけで、業務ロジックは持たない）。

## `player.ts` に用意するもの — `PlaybackController` の実装

`src/service/player.ts` で定義している `createPlaybackController` の型を満たす関数を実装する。

```ts
(options: CreatePlaybackControllerOptions) => Promise<PlaybackController>
```

`CreatePlaybackControllerOptions`

| プロパティ | 役割 |
| --- | --- |
| `containerId: string` | 再生エンジンの DOM 要素を差し込むコンテナの `id` |
| `trackId: string` | 再生開始する曲の ID |
| `autoplay: boolean` | 生成直後に自動再生するかどうか |
| `onStateChange: (state: PlaybackState) => void` | 再生状態が変化したときのコールバック |

`PlaybackState` は `"cued" \| "playing" \| "paused" \| "ended"` の4値。中間的な状態（バッファリング中など）は通知しない（呼び出し側の UI がちらつくのを防ぐため）。

返り値の `PlaybackController`

| メソッド | 役割 |
| --- | --- |
| `play()` / `pause()` | 再生/一時停止 |
| `loadTrack(trackId)` | 別の曲を読み込み、自動再生する |
| `cueTrack(trackId, startSeconds?)` | 別の曲を読み込むが自動再生しない（`startSeconds` 指定でその位置から一時停止状態でロード） |
| `seekTo(seconds, allowSeekAhead)` | 再生位置の変更 |
| `setVolume(volume)` | 音量設定（0〜100） |
| `getCurrentTime()` / `getDuration()` | 現在の再生位置・曲の長さ（秒） |
| `destroy()` | 再生エンジンの破棄（アンマウント時に呼ばれる） |

`createPlaybackController` は `options.containerId` の要素が見つからない場合は reject してよい（呼び出し側の `player/hook.ts` は `.catch()` で握りつぶす）。

## `authScope.ts` に用意するもの

NextAuth の OAuth スコープなど、認証に関わる定数のみを置く。**他のファイル（特に `api.ts`）を import しないこと。** `src/auth.ts` がこの定数を直接 import しており、`auth.ts` → `adapter.ts`（`auth()` を使う）→ `authScope.ts` → `auth.ts` という循環参照を避けるため、依存を持たない独立ファイルにする必要がある。

## チェックリスト

- [ ] `api.ts`：認証・HTTP 通信・（必要なら）クォータ計測
- [ ] `adapter.ts`：`ServiceAdapter` の全メンバーを実装し、entity はサービス非依存の形にマッピングする
- [ ] `player.ts`：`createPlaybackController` を実装し、`PlaybackState` の4値に正しくマッピングする
- [ ] `authScope.ts`：他ファイルに依存しない形でスコープ定数を定義
- [ ] `src/service/adapter.ts`・`src/service/player.ts` の参照先を新しい vendor に切り替える
- [ ] OAuth の認証方式自体が異なる場合は `src/auth.ts` の NextAuth プロバイダ設定を変更する
- [ ] `bunx tsc --noEmit`・`bun run lint`・`bun run build` が通ることを確認する
